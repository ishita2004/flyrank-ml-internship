Applied Search Intelligence: Prioritizing Content Refresh via Client-Holdout Machine Learning

Author: Ishita Chaubey • Track: Machine Learning • Date: August 26, 2026 • Code Repo: ishita2004/flyrank-ml-internship

1. Title & Abstract

Abstract: Content marketing teams manage large portfolios of published articles but possess limited weekly audit capacity. This research addresses how machine learning models can combine organic search exposure, rank decay, click-through rates, and content freshness signals to prioritize published pages for editorial refresh review. Using a dataset of 28,795 candidate articles across 32 clients, we evaluated baseline heuristics against machine learning models using a strict GroupShuffleSplit client-holdout validation design. Our Random Forest model achieved a Precision@50 of 0.740 on unseen client holdouts—outperforming the hand-written rule baseline (0.240) by 3.0x. The system outputs an evidence-backed priority ranking with reason codes, allowing editorial teams to maximize traffic recovery per hour of review time.

2. Introduction & Problem Statement

Large content websites experience continuous organic search position decay over time as articles become stale. However, editorial teams face a severe operational bottleneck: a team might only have bandwidth to review 20 to 50 articles per week out of a portfolio of 30,000+ published URLs.

Traditional approaches rely on simplistic, static rules (e.g. age >= 180 AND impressions >= 500). These rules create massive tied blocks at the top of the queue and fail to account for non-linear interactions between SERP position tiers, impression volume, and CTR cliffs. This work supports the operational decision of queue prioritization—ordering candidate articles by predicted decay risk and traffic opportunity so editors spend their hours on highest-leverage assets first.

3. Data Summary & Public-Safe Exclusions

This study utilizes the FlyRank anonymized search performance dataset release (data/raw/content_refresh_anonymized.csv), verified against FlyRank/internship-warehouse schema v20260703.

  • Grain (Unit of Analysis): One row = One pseudonymized content item (content_id) for a specific client (client_id).
  • Candidate Filtering: Filtered to active candidate pages with impressions_90d > 0 and content_age_days >= 90 (yielding 28,795 candidate rows).
  • Time Window: Trailing 90-day search performance window prior to snapshot date.
  • Public-Safe Exclusions: All raw client domains, URLs, and private search queries were stripped. Crucially, trend_direction and trend_pct were explicitly barred from model input features to prevent target leakage.

4. Methodology & Validation Design

The modeling task is framed as a Priority Ranking Problem backed by probabilistic binary classification.

Component Specification
Target Label is_declining_label = (trend_direction == 'down') (Proxy for active search traffic decay).
Input Features (5 Signals) impressions_90d, days_since_last_update, avg_position, ctr, word_count.
Validation Design Client-Holdout (GroupShuffleSplit) splitting on client_id (80% train / 20% test). Models are tested strictly on unseen client domains.
Leakage Safeguards Barred trend_pct from inputs. In deliberate leakage tests, including trend_pct inflated scores to an artificial 1.000; removing it restored honest validation.

5. Experimental Results

Models were evaluated using Precision@50—measuring what fraction of the top 50 recommended pages on the unseen holdout set were genuinely declining assets.

Method / Model Validation Split Precision@50 Multiplier vs Baseline
Hand-Written Rule Baseline Client Holdout 0.240 1.0x
Logistic Regression Client Holdout 0.480 2.0x
Decision Tree (depth=3) Client Holdout 0.540 2.25x
Random Forest (n=100) Client Holdout 0.740 3.08x Best Model

Key Finding: The Random Forest model achieves a 0.740 Precision@50, meaning 37 out of the top 50 flagged pages are confirmed declining high-traffic pages, compared to only 12 out of 50 for the rule baseline.

6. Limitations & Honest Framing

  • Observational, Not Causal: The model identifies high-risk/opportunity candidates based on historical search patterns. It does not prove causal traffic recovery upon updating (requires future A/B testing).
  • Algorithm Disclaimer: This work does not reverse-engineer search engine ranking algorithms.
  • Zero-Position Masking: avg_position = 0 indicates missing Search Console position data (1,205 rows), requiring explicit boolean flag masking to avoid rank distortion.
